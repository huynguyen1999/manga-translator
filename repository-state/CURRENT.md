# Current state

Last reviewed: 2026-09-22

## Active feature — unified canonical layout, mask, and rendering pipeline

- Studio (`MangaTranslator`, `batch_scheduler.py`) and devscripts (`pipeline_step_runner.py`) are unified into a single canonical pipeline.
- Mask generation is unified into `manga_translator/mask_builder.py` (`MaskBundle`, `build_inpaint_masks`), computing identical detector cleanup, text, bubble, and inpaint masks across both batch studio jobs and CLI runner captures.
- Speech bubble detections are serialized and persisted to `bubble_detections.json` during batch preparation and reloaded during translation/rendering, eliminating duplicate YOLO inference passes.
- Studio stage serialization (`serialize_regions` and `deserialize_textblocks`) losslessly preserves `source_font_size`, `calibrated_font_size`, `placement_mode`, `source_region_ids`, `source_regions`, and `bubble_safe_shape`.
- Text rendering is unified into the canonical `render_page()` function in `manga_translator/rendering/__init__.py`, guaranteeing bit-level pixel and geometry parity between Web Studio translations and devscripts fast renders.

## Active migration — production layout boundary

- `manga_translator/rendering/layout/` owns page-layout data contracts, extracted bubble-mask geometry/lobe detection, page obstacle masks, free-text ownership targets, and non-fatal layout validation.
- `layout_page()` runs after final mask generation and before inpainting; it runs the shared shape-aware solver used by the pipeline runner, then freezes the result for rendering and diagnostics.
- `TextBlock` and grouped bubble regions preserve `region_id`, `source_region_ids`, and per-source geometry snapshots for ID-based edits and multi-region placement.
- Bubble association keeps same-bubble OCR regions separate by default; merging is opt-in through `BubbleDetectionConfig.group_regions` or the dev runner's `--bubble-grouping` flag.

## Purpose

Manga Image Translator translates text in manga and other images through a pipeline of detection, OCR, translation, inpainting, and rendering. It supports command-line, desktop, API/server, and browser-based workflows.

## Main areas

- `manga_translator/`: core Python translation pipeline and model integrations.
- `server/`: web API, persistence, scheduling, streaming, search, and summaries.
- `front/`: React 19 and React Router 7 web studio.
- `MangaStudio_Data/`: desktop studio configuration, profiles, UI data, and tasks.
- `devscripts/`: developer evaluation, benchmarking, maintenance utilities, and the pipeline step runner (`pipeline_step_runner.py`, `capture_step_data.py`, `fast_render.py`) for capturing English or raw manga OCR/bubble/inpainting data (with optional translation support via `--sugoi` / `--translator sugoi`) to `devscripts/data` and testing fast text placement, fitting, and rendering (with `--no-bubble-grouping` option to keep individual text regions separate instead of merging them per bubble). Separate regions that share a bubble are laid out jointly with source-anchored placement zones. The shared shape-aware solver (`manga_translator/rendering/layout/solver.py`) enforces a structural **continuous paragraph rhythm** invariant ($y_i^* = y_0 + i H$), bidirectional spring-chain vertical compaction (`_compact_vertical_rhythm` with continuous Y sub-row search and precomputed `_build_row_slot_table`), tightened geometric obstruction checks (`_is_geometric_obstruction`), staged candidate generation and pruning across line-count diversity buckets before expensive geometric refinement passes, bounded ephemeral mask/band cache lifecycles (`clear_ephemeral_caches`), feasibility-bounded block recentering (`_center_layout_block`), explicit adjacent gap classification (`_classify_adjacent_gaps`), and coarse-to-fine hierarchical font sizing and Y-origin search. Level-2 profiling (`SolverProfileStats`) instruments fine-grained layout sub-phase timings and workload counters (DP calls/states/dedup, Y trials, font trials, cache hits/misses, crop rasters) reported in `--solver-report`.
- The `typediag` diagnostic subsystem in `pipeline_step_runner.py` provides standalone font-metrics and typography rendering correctness validation across 10 phases: `render-test` (layout-bypass test with metric guide lines and glyph bounding boxes), `trace` (per-character resolution path and determinism verification), `scale-audit` (AST/source inspection and runtime checks for unauthorized per-character scaling), `cache-audit` (face-keyed glyph cache coverage), `validate` (batch verification of font and size consistency per text region across datasets), and `fixtures` (golden reference visual regression test suite). It establishes the `FontContext` immutable typography configuration dataclass, decoupling requested size from glyph ink height ($H_{\text{ink}} = \text{ascender} - \text{descender}$) and line height ($H_{\text{line}}$). Fast render now resolves one active font for both solver measurement and final rasterization, and `--solver-report` includes per-region typography face/size/fallback diagnostics.
- The pipeline step runner now calls the shared solver and classifies each region once after bubble association: `BUBBLE` keeps the existing `BubbleGeometry → solve_layout()` path, while `FREE_TEXT` uses `FreeTextDamageTarget`/`FreeTextZone` for region-specific inpaint footprints. Free text first generates whole-word, page-independent typography candidates using source font/aspect priors and actual glyph-ink footprint metrics, freezes the chosen paragraph with one natural baseline rhythm, then centers its rendered ink on the source-plus-inpaint target centroid and searches rigid offsets while allowing expansion beyond the source ownership partition into blank page space. Free-text candidates are ranked and bounded (top 16 per region) for fast joint selection without large Cartesian product overhead. Page, bubble-halo, foreign-text, and actual-glyph collision constraints remain hard; target dimensions influence font size and wrapping, never inter-line stretching. `--solver-report` and `free_text_layout_debug.png` expose source/inpaint/target and ink footprints, baseline rhythm, coverage, typography alternatives, and final offsets.
- Non-bubble capture/render state preserves stable region IDs, grouped source ownership, the exact final inpaint mask, and an OCR → translation → layout → render trace; editable region JSON is applied by ID rather than list position.
- Fast render timing now breaks the layout total into mask preparation, placement-mode classification, bubble solving, free-text solving, fallback placement, and uninstrumented remainder in the batch summary, with Level-2 profiling stats.
- The row DP treats leading/trailing whitespace separately from paragraph-internal whitespace: usable rows form a continuous text stack, unavailable bands remain geometry-forced traversals, and excess line-to-line distance is penalized nonlinearly.
- `docs/`: focused technical and experimental documentation.

## Translation pipeline

- Translation settings offer `fast` (the existing batched path) and `professional` Japanese-to-English localization. Professional mode waits for the complete submitted group, analyzes OCR-only story boundaries, applies optional page-range overrides, translates pages sequentially with rolling context (bounded to 8 000 chars in memory), enforces native LLM JSON mode (`response_format` / `response_mime_type`) with resilient cutoff parsing, routes adult-content refusals and JSON-format failures to DeepSeek, runs a separate editor pass, persists `professional_translation.json`, and renders while flagging uncertain regions for review. Image memory is minimized: pages are loaded from disk one at a time immediately before rendering and released immediately after (`ctx._deferred_image_path` pattern in `batch_scheduler.py`); concurrent renders are bounded by `_RENDER_SEMAPHORE_SIZE = 2` so peak image memory equals at most two decoded pages regardless of job size.
- Professional submissions use a two-step group/story dialog. ZIP/CBZ pages retain archive identity, default to one story per archive, support contiguous manual split markers via an interactive visual filmstrip with draggable boundary handles, hover gap split creation, color-coded story bands, a right-side high-resolution page preview and cut-off boundary inspector (side-by-side transition preview), optional OCR-time break detection, and an explicit merge-all-pages mode. The structured `storyPlan` is persisted with each batch and audit document; draft/editor requests use the configured page batch size but never cross story boundaries; the legacy `storyPageRanges` setting remains accepted for compatibility.
- Professional progress is surfaced as `Analyzing story`, `First draft · Story x/y · Chunk a/b`, and `Editor pass · Story x/y · Chunk a/b`; completed page details show the persisted Japanese source, first draft, editor final, confidence, and review reasons from `professional_translation.json`. The first pass is intentionally an accurate working draft, while the editor independently rechecks it for natural localization.
- Page details also expose the persisted professional story analysis: summaries, page boundaries, confidence, characters, relationships, voice notes, continuity, glossary, and ambiguities.
- Batch size counts translatable pages. OCR regions inside one detected speech bubble are grouped into one translation unit; unmatched regions remain individual units.
- Batch preparation generates `text_mask.png` and a safe inset `bubble_mask.png`, unions them into `mask_final.png`, and finishes inpainting before the AI translation request.
- Default English rendering font resolution (`get_default_eng_font()`) prioritizes Wild Words (`Wild Words.ttf`, `CC Wild Words Roman.ttf`, `wild_words.ttf`, etc.) when present in `fonts/`, falling back gracefully to bundled comic fonts (`anime_ace.ttf` / `comic shanns 2.ttf`).
- Translated-text placement runs after the response. Units with available translations are rendered onto the canvas even when flagged for manual review, with page-level baseline coordination, consistent font sizing, adaptive multi-line placement with relaxed bubble overflow fallback, and inpainting; failed/missing translation units restore their original pixels instead of leaving empty bubbles.
- Review-flagged text regions are rendered onto the canvas across backend pipeline rendering and web studio preview/editor while retaining explicit review flags, reasons, and badge indicators for subsequent review, draft saving, and approval in the studio.
- Speech bubble layout operates directly on arbitrary 2D free-space masks rather than rigid bounding boxes: uses Euclidean distance fields (SDF) to compute medial axes and boundary clearances, calculates spatial mask moments ($C_M, \Sigma_M$) and text inertia tensors ($C_T, \Sigma_T$) for orientation and aspect alignment, employs DP line breaking across horizontal span contours $C(y)$, and evaluates candidate layouts against centroid offset, inertia disparity, capacity utilization (~55–65% fill target with word-length bounds), raggedness, and linguistic boundaries. Candidate scoring accounts for FreeType ascender/descender metrics to avoid artificial box overflow, while prepared single-lobe and multi-lobe boxes composite directly into canvas points. Connected and multi-lobe bubbles balance word counts proportionally across spatial capacity while preserving uniform font sizing (with bounded per-lobe scaling when necessary), validating all glyph pixels against the safe shape with SDF margin clearance.
- Neural network model inference (detectors, OCR, bubble detection, inpainting, translators, upscalers) is synchronized through `SharedModelExecutor` and serialized via `_mps_call` on Apple Silicon MPS to avoid multi-threaded Metal command buffer races.
- Text detector checkpoints live under `models/detection/`; optional speech-bubble segmentation checkpoints live separately under `models/bubbles/`.
- Raw text detection bounding boxes (`detection.json`) and OCR textlines (`ocr.json`) are persisted immediately to disk and database storage upon stage completion, guaranteeing access to raw segmentation data prior to any downstream bubble grouping or translation filtering.
- The page-detail and preview image components display detector polygon outlines color-coded by confidence tier (emerald $\ge 85\%$, amber $65\%-84\%$, rose $< 65\%$) with interactive hover highlights and floating tooltips showing exact confidence percentages (e.g. `#4 · 94% · high`), eliminating visual clutter on multi-line Japanese text.
- The web studio exposes OCR model selection and OCR Minimum Confidence threshold (`customOcrProb` / `ocrMinConfidence`), mapped to `OcrConfig.prob` and persisted across settings, batch jobs, pipeline lab, and pipeline manifest metadata.
- Manga OCR (`mocr`, `kha-white/manga-ocr-base`) downloads complete model assets directly into `./models/ocr/` and loads offline from that directory when present; `docker_prepare.py` supports preparing `mocr` via `--models ocr.mocr` (or `mocr`).
- Result metadata (`meta.json` and `pipeline_manifest.json`) captures comprehensive pipeline step parameters (detector, resolution, box threshold, unclip ratio, OCR model, OCR min confidence, bubble detection settings, inpainting parameters, rendering configurations, colorizer, and upscaler); the web studio `PageDetailModal` displays these in a tabbed resizable sidebar with four tabs — Pipeline Timing (started/ended/duration + per-stage breakdown), Professional Localization, Story Analysis, and Step Settings (translation details + all step parameters). The sidebar defaults to 480 px wide and is drag-resizable from its left edge (280–700 px range).
- The web studio reacts to batch SSE events by refreshing active and completed batch item details in the background, ensuring completed page results, folders, and thumbnails are immediately clickable and viewable in the studio without page refresh.
- Dropping or uploading loose image files loads them directly into the studio cards list without intermediate staging, while multi-archive drops retain volume arrangement before extraction. Manga detail gallery supports smooth proximity-accelerated vertical auto-scrolling when dragging pages near viewport edges during page reordering. Selecting multiple pages or multiple manga cards supports batch deletion with confirmation prompts and atomic cache and state invalidation.
- Translated text lettering case can be configured to original (mixed case), ALL CAPS (uppercase), or lowercase across CLI arguments (`--uppercase`, `--lowercase`, `--letter-case`), server batches, Web Studio options panel, and Pipeline Lab; English typesetting segmenters preserve original case without hardcoded upper-casing.
