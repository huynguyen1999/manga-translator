Last reviewed: 2026-09-24

## Backend UI surface
- The API server no longer serves the legacy HTML translator at `/`; port 8000 serves API routes and OpenAPI docs at `/docs`. The separate browser Studio remains under `front/` on port 6868.

## Reader mobile navigation
- Touch readers use a dedicated, full-width page jump row with a numeric keyboard and 44px controls; desktop keeps its compact toolbar input.

## Active feature — original manga CBZ export
- Manga library downloads offer translated and original CBZ archives. Original exports use each page's retained source image and name the archive with an `_original` suffix.

## Active optimization — page-local layout profiling and reusable free-text rasters
- Solver counters now belong to one layout execution. The line-alpha cache includes the active font selection; candidate ink, visual, and block masks are reused across placement offsets, and final QA rasterizes overflow from those cached masks.
- Row-slot, placement-target, and zone-profile results are cached for the lifetime of one page layout. Long-word pressure reads a cached row maximum or computes only that maximum; hyphenation rescue skips splits that cannot fit or improve the bottleneck.
- Free-text search retains the existing score and exhaustive fallback while deferring full QA until the best eight candidates. Strict ideal placements are attempted by default; `LAYOUT_FAST_FREE_TEXT=0` disables the ideal stage, and `LAYOUT_LAZY_CANDIDATES=1` independently enables local candidates. Multiple free-text regions use exact joint collision checks and rerun exhaustive search for colliding fast placements. `--layout-shadow-compare` returns the exhaustive layout. Row-slot bands use vertical prefix counts; DP word-run widths use prefix sums, compaction visits only feasible Y positions, and composite whitespace scoring reuses row/column counts.
- `python devscripts/pipeline_step_runner.py layout-benchmark --dataset devscripts/data --repeat 5` reports layout percentiles and solver counters by page category. The current local dataset contains one sample page; shadow comparisons on a larger corpus should quantify candidate-quality differences.

## Active developer tool — local semantic-search lab

The thin Colab/Jupyter frontend is `devscripts/semantic_search_lab_colab.ipynb`; no database or server is required.

## Active developer tool — manga panel detection & segmentation (YOLO26)
- `devscripts/detect_panels.py` runs inference with both `ShadowB/Manga109-panel-balloon-text-yolov26-segmentation` (YOLO26s instance segmentation for panels, balloons, and text with polygon masks) and `leoxs22/manga-panel-detector-yolo26n` (YOLO26n panel and text detector). It handles automatic checkpoint downloading from Hugging Face, Ultralytics serialization shims (`Segment26`, `Proto26`, `E2ELoss`), RTL/LTR reading-order sorting, retina mask overlays, panel cropping, and metadata JSON generation.



## Active feature — memory-aware shared model cache
- The shared executor tracks each cached model's last use and active users. Idle entries expire after the server's 120-second default, with `--models-ttl 0` retaining them indefinitely; under 60% process-RAM pressure it evicts idle entries by LRU, and at 72% it performs full idle eviction and synchronized device-cache cleanup.
- Model unload paths invoke backend unload hooks, including detector reference cleanup. Bubble model identity is checkpoint/device only, with confidence, mask threshold, and image size passed per inference.
- Detection no longer copies unmodified source pages. 48px OCR and MangaOCR generate crop microbatches instead of retaining all page crops; scheduler page groups cap at 3 for detection/OCR/bubbles and 2 for upscaling/inpainting, with smaller groups as process RSS approaches the memory threshold.

## Pipeline run records
- Pipeline stage boundaries log process RSS, Python GC object count, MPS allocated/driver memory, batch/page identity, and RSS delta at DEBUG level; server console verbosity defaults from `LOG_LEVEL` in `.env` and can be overridden with `--log-level` or `--verbose`. Mask diagnostics are dropped before layout; `Context.cleanup_runtime()` drops saved page buffers and layout scratch on run release while retaining requested result canvases. Final mask aliases avoid one full-page copy, legacy `translate_batch()` prepares bounded chunks, and MPS inpainting is capped at 1024px to reduce full-page float32 activation peaks. Batch completion clears translator page-history state and synchronizes/empties device caches without unloading shared models.
- GPU inference logs identify detection/OCR page groups, MangaOCR crop groups, YOLO bubble-prediction page counts, and actual inpainting tensor batch/device. Upscaler logs distinguish UltraSharp tensor batches from one-item tile calls and NCNN-Vulkan directory-process inputs.
- Server-generated stage manifests provide per-page timing and preserve batch retry/resume data; active batch rows show elapsed time from the persisted stage start, and job cards show the current pipeline stage with the number of pages that have passed it. Repeated progress signals for an unchanged stage do not write a new manifest revision. Standalone Pipeline Lab navigation, upload shortcut, history, and manual stage controls are removed.
- Queued batch rows show the next scheduled pipeline stage when known, or whether they are waiting to start or for a batch slot.
- In-process manga batches use a job-wide stage barrier: every nonterminal page completes the current stage before any page enters the next. The order is colorization, upscaling, detection, OCR, bubble detection, text grouping, translation, mask generation, layout, inpainting, and rendering. Accelerator model calls remain serialized; page groups for compatible 48px OCR (including CTC), MangaOCR, default detection, YOLO bubble detection, and default AOT inpainting target the `--workers` count. OCR crop calls include at least one crop per grouped page and grow beyond 16 rows when needed. MangaOCR batches crops across pages for both text generation and its auxiliary confidence/color model, with generation chunks sized to at least the page-group count. MPS default and DBConvNeXt detection batches run at worker count in one FP16-autocast inference call to limit activation memory; MPS out-of-memory errors remain on the accelerator path instead of retrying on CPU. Inpainting batches only combine shapes with at most 25% padding overhead; LaMa Large and MPE stay single-page for model-memory and positional-encoding limits. CPU-only inference can also batch compatible pages in worker-sized groups. Translation uses its configured page/story groups after all pages clear preparation. Translation documents are checkpointed before mask generation, and post-translation work resumes from persisted page stages. A failed page blocks the batch until retry or removal; completed textless pages count as skipped. A cached inpainted image without its active mask is discarded and rebuilt. Mutable-store stage-barrier batches require an in-process checkpoint-capable executor; remote whole-page workers are not selected for them.
- `manga_translator/pipeline/stages.py` defines canonical stage IDs (including optional colorization), resources, dependencies, progress mapping, settings invalidation, and stable JSON fingerprints. In-process batch scheduling configures resource-class limits from pipeline workers; accelerator-backed model stages serialize through one GPU slot and stay on the configured device while waiting. Background CPU auto-caps at 3 with two slots available when at least two pipelines are configured, or can be set by --cpu-stage-workers; light CPU uses the same budget; network 4; I/O 4. One process-wide background CPU pool enforces the heavy-stage budget across executor loops, with one reserved interactive slot. Layout uses per-thread FreeType state and runs without the page-wide render lock, so independent pages can use those CPU slots concurrently. Default/DBNet detection, including on MPS, batches compatible pages up to the configured `--workers` count. The UI-default 48px OCR, 48px CTC, and MangaOCR paths batch compatible pages up to the same count, including when verbose logging is enabled; compatible YOLO bubble pages and default AOT inpainting use that target. Inpainting tensor batches allow no more than 25% padding overhead. LaMa Large and MPE remain single-page; 32px OCR keeps the single-page path. Pipeline reruns invalidate dependency closures and persist stage attempts for indexed pages in PostgreSQL; the existing page timing endpoint overlays those records. Checkpoint manifests persist layout output and support automatic failed-stage or explicit `fromStage` retry; checkpoint-backed items enter the resume processor through the normal batch scheduler. Retry plans use the dependency graph: Translation retries preserve mask/inpainting outputs, while OCR retries rebuild text grouping from saved bubble geometry and rerun dependent stages. Page timing responses include direct dependencies so per-stage retry previews use the server graph. Scheduler startup closes unfinished database attempts as interrupted.
- PostgreSQL migration `013_pipeline_stages.sql` adds per-page stage state and attempt history plus revisioned structured-document and artifact registries. Indexed reruns persist stage attempts and atomically activate versioned artifact/document revisions; existing final/inpainted/mask URLs serve the active revision. Normal batch result indexing imports finished canonical stage records, recognized structured JSON, and completed disk-artifact metadata into PostgreSQL; other documents stay in the compatibility document store.
- Professional translation groups pages by configured story segments and rebases the selected segment and archive ranges before translation. The batch-wide stage barrier holds all stories when any page fails, until that page is retried or removed.
- PostgreSQL batch mutations lock the batch row across read-modify-write, and batch/item status and stage reads hydrate from relational columns; the manifest remains a compatibility payload. Item stage start times persist in PostgreSQL, so scheduler claims and progress updates serialize and read back consistently across backend processes.

## Active feature — unified canonical layout, mask, and rendering pipeline

- Studio (`MangaTranslator`, `batch_scheduler.py`) and devscripts (`pipeline_step_runner.py`) are unified into a single canonical pipeline.
- Mask generation is unified into `manga_translator/mask_builder.py` (`MaskBundle`, `MaskMetrics`, `build_inpaint_masks`, `recover_bubble_residual_text`, `create_mask_sources_overlay`), computing identical detector rescue, text, bubble residual, and inpaint masks across both batch studio jobs and CLI runner captures.
- Bubble geometry is prepared once as `geometry.PageGeometry` and reused by mask construction and layout. Per-bubble cleanup/edge geometry is crop-local, with the safe interior retained only for current layout and serialization compatibility; one page-wide protected-edge mask is shared.
- `MaskBundle.profile` records refinement, geometry, detector cleanup, residual recovery, composition, and workload metrics; Studio and CLI captures persist it as `profiling.json`.
- Text-component growth and ignored-bubble dilation operate on component crops. Layout debug rendering is opt-in, candidate collision work uses crop masks, and free-text ownership plus region identity preparation each have one shared implementation.
- Canonical inpaint composition treats detector/refined text evidence as authoritative. Bubble preparation now exposes safe geometry plus a narrow source-image outline protection mask; final text growth is component-constrained and protected pixels are restored after inpainting.
- Residual text recovery inside speech bubbles (`recover_bubble_residual_text`) uses dual global & adaptive Gaussian thresholding, safe bubble interior erosion, orientation-aware text envelopes, and connected-component filtering to completely erase OCR-missed characters/punctuation (e.g. trailing `!?`, kana fragments, gray antialiased glyphs) while strictly protecting bubble outer borders (`final_mask ∩ protected_bubble_edge == ∅`).
- Mask diagnostic artifacts (`mask_raw.png`, `text_mask.png`, `detector_rescue_mask.png`, `bubble_residual_mask.png`, `protected_bubble_edge.png`, `inpaint_mask.png`, `mask_final.png`, `mask_sources_overlay.png`) are persisted across Studio debug outputs and devscripts capture step data.
- Speech bubble detections are serialized and persisted to `bubble_detections.json` during batch preparation and reloaded during translation/rendering, eliminating duplicate YOLO inference passes.
- Studio stage serialization (`serialize_regions` and `deserialize_textblocks`) losslessly preserves `source_font_size`, `calibrated_font_size`, `placement_mode`, `source_region_ids`, `source_regions`, and `bubble_safe_shape`.
- Text rendering is unified into the canonical `render_page()` function in `manga_translator/rendering/__init__.py`, guaranteeing bit-level pixel and geometry parity between Web Studio translations and devscripts fast renders.
- `render_page()` partitions restoration from drawing: suppressed regions are restored once before rendering and excluded from all renderers; valid review-required fallback translations still draw.
- FREE_TEXT regions use conservative CV frame-line inference to constrain wrapping and the full paragraph box to the source panel, with fallback to page bounds when no reliable panel edge is found. Bubble solving is unchanged.

## Active migration — production layout boundary

- `manga_translator/rendering/layout/` owns page-layout data contracts, extracted bubble-mask geometry/lobe detection, page obstacle masks, shared free-text ownership targets, region identities, crop-local candidate rasterization, and non-fatal layout validation.
- `layout_page()` runs after final mask generation and before inpainting; it runs the shared shape-aware solver used by the pipeline runner, then freezes the result for rendering and diagnostics.
- Versioned `layout.json` is the authoritative `FrozenLayout`: it stores stable region/bubble IDs, selected styles, safe bubble shape, exact positioned lines, and fingerprints for translations, source geometry, bubble geometry, mask, font, settings, and page size. Rendering hydrates by region ID and rasterizes those lines without reflow; `translations.json` remains the text source. Rare unresolved legacy placements retain their validated RGBA crop.
- Bubble layout uses a robust page dialogue baseline as its preferred target; long words do not cap adaptive font estimates, and preserved annotations do not affect the baseline or receive inserted hyphens. The non-hyphenated solve remains primary; one legal split of an 8+ letter bottleneck word may replace it after a meaningful font gain. `no_hyphenation` disables rescue, and comparison diagnostics persist in `layout.json`.
- `TextBlock` and grouped bubble regions preserve `region_id`, `source_region_ids`, and per-source geometry snapshots for ID-based edits and multi-region placement.
- Bubble association persists stable `bubble_id` values so separate OCR regions in one speech bubble remain jointly optimized after checkpoint reload. Merging remains opt-in through `BubbleDetectionConfig.group_regions` or the dev runner's `--bubble-grouping` flag.

## Purpose

Manga Image Translator translates text in manga and other images through a pipeline of detection, OCR, translation, inpainting, and rendering. It supports command-line, desktop, API/server, and browser-based workflows.

## Main areas

- `manga_translator/`: core Python translation pipeline and model integrations.
- `server/`: web API, persistence, scheduling, streaming, search, and summaries.
- `front/`: React 19 and React Router 7 web studio.
- `MangaStudio_Data/`: desktop studio configuration, profiles, UI data, and tasks.
- `devscripts/`: developer evaluation, benchmarking, maintenance utilities, and the pipeline step runner (`pipeline_step_runner.py`, `capture_step_data.py`, `fast_render.py`) for capturing English or raw manga OCR/bubble/inpainting data (with optional translation support via `--sugoi` / `--translator sugoi`) to `devscripts/data` and testing fast text placement, fitting, and rendering (with `--no-bubble-grouping` option to keep individual text regions separate instead of merging them per bubble). Separate regions that share a bubble are laid out jointly with source-anchored placement zones. The shared shape-aware solver (`manga_translator/rendering/layout/solver.py`) enforces a structural **continuous paragraph rhythm** invariant ($y_i^* = y_0 + i H$), bidirectional spring-chain vertical compaction (`_compact_vertical_rhythm` with continuous Y sub-row search and precomputed `_build_row_slot_table`), tightened geometric obstruction checks (`_is_geometric_obstruction`), staged candidate generation and pruning across line-count diversity buckets before expensive geometric refinement passes, bounded ephemeral mask/band cache lifecycles (`clear_ephemeral_caches`), feasibility-bounded block recentering (`_center_layout_block`), explicit adjacent gap classification (`_classify_adjacent_gaps`), and coarse-to-fine hierarchical font sizing and Y-origin search. Level-2 profiling (`SolverProfileStats`) instruments fine-grained layout sub-phase timings and workload counters (DP calls/states/dedup, Y trials, font trials, cache hits/misses, crop rasters) reported in `--solver-report`.
- The `typediag` diagnostic subsystem in `pipeline_step_runner.py` provides standalone font-metrics and typography rendering correctness validation across 10 phases: `render-test` (layout-bypass test with metric guide lines and glyph bounding boxes), `trace` (per-character resolution path and determinism verification), `scale-audit` (AST/source inspection and runtime checks for unauthorized per-character scaling), `cache-audit` (face-keyed glyph cache coverage), `validate` (batch verification of font and size consistency per text region across datasets), and `fixtures` (golden reference visual regression test suite). It establishes the `FontContext` immutable typography configuration dataclass, decoupling requested size from glyph ink height ($H_{\text{ink}} = \text{ascender} - \text{descender}$) and line height ($H_{\text{line}}$). Fast render now resolves one active font for both solver measurement and final rasterization, and `--solver-report` includes per-region typography face/size/fallback diagnostics.
- The pipeline step runner now calls the shared solver and classifies each region once after bubble association: `BUBBLE` keeps the existing `BubbleGeometry → solve_layout()` path, while `FREE_TEXT` uses `FreeTextDamageTarget`/`FreeTextZone` for region-specific inpaint footprints. Free text first generates whole-word, page-independent typography candidates using source font/aspect priors and actual glyph-ink footprint metrics, freezes the chosen paragraph with one natural baseline rhythm, then centers its rendered ink on the source-plus-inpaint target centroid and searches rigid offsets while allowing expansion beyond the source ownership partition into blank page space. Free-text candidates are ranked and bounded (top 16 per region) for fast joint selection without large Cartesian product overhead. Page, bubble-halo, foreign-text, and actual-glyph collision constraints remain hard; target dimensions influence font size and wrapping, never inter-line stretching. `--solver-report` and `free_text_layout_debug.png` expose source/inpaint/target and ink footprints, baseline rhythm, coverage, typography alternatives, and final offsets.
- Non-bubble capture/render state preserves stable region IDs, grouped source ownership, the exact final inpaint mask, and an OCR → translation → layout → render trace; editable region JSON is applied by ID rather than list position.
- Fast render timing now breaks the layout total into mask preparation, placement-mode classification, bubble solving, free-text solving, fallback placement, and uninstrumented remainder in the batch summary, with Level-2 profiling stats.
- The row DP treats leading/trailing whitespace separately from paragraph-internal whitespace: usable rows form a continuous text stack, unavailable bands remain geometry-forced traversals, and excess line-to-line distance is penalized nonlinearly.
- `docs/`: focused technical and experimental documentation.

## Translation pipeline

- Translation settings offer `fast` (the existing batched path) and `professional` Japanese-to-English localization. Professional mode waits for its configured page/story group, analyzes OCR-only story boundaries and structured linguistic register (character voice, dialect, slang, idioms, pronouns, honorifics/forms of address, and localization conventions), uses neutral compact analysis instructions and fidelity-focused draft/editor instructions, applies optional page-range overrides, translates pages sequentially with rolling context (bounded to 8 000 chars in memory), enforces native LLM JSON mode (`response_format` / `response_mime_type`) with resilient cutoff parsing, routes adult-content refusals and JSON-format failures to DeepSeek, runs a separate editor pass, persists `professional_translation.json`, and flags uncertain regions for review. Both modes translate from OCR checkpoints without loading page pixels; mask, layout, inpainting, and rendering run later under the job-wide stage barriers.
- Professional submissions use a two-step group/story dialog. ZIP/CBZ pages retain archive identity, default to one story per archive, support contiguous manual split markers via an interactive visual filmstrip with draggable boundary handles, hover gap split creation, color-coded story bands, a right-side high-resolution page preview and cut-off boundary inspector (side-by-side transition preview), optional OCR-time break detection, and an explicit merge-all-pages mode. The structured `storyPlan` is persisted with each batch and audit document; draft/editor requests use the configured page batch size but never cross story boundaries; the legacy `storyPageRanges` setting remains accepted for compatibility. Pixel-backed page work resumes from persisted inputs and stage artifacts after translation.
- Professional progress is surfaced as `Analyzing story`, `First draft · Story x/y · Chunk a/b`, and `Editor pass · Story x/y · Chunk a/b`; completed page details show the persisted Japanese source, first draft, editor final, confidence, and review reasons from `professional_translation.json`. The first pass is intentionally an accurate working draft, while the editor independently rechecks it for natural localization.
- Page details also expose the persisted professional story analysis: summaries, page boundaries, confidence, structured character voice, honorific policy, language features, localization conventions, relationships, voice notes, continuity, glossary, and ambiguities. The analysis establishes non-stereotyping dialect treatment and story-level consistency rules for the draft and editor.
- Batch size counts translatable pages. OCR regions inside one detected speech bubble are grouped into one translation unit; unmatched regions remain individual units. Fast page groups flatten those units into one ordered provider list; DeepL sends native text-array requests, splitting only at its 128 KiB request limit, and maps ordered responses back to their regions. Translation starts only after every active page completes OCR, bubble detection, and text grouping; downstream mask/layout/inpainting/render stages also wait for the full preceding stage.
- Batch checkpoints persist detection, OCR, bubble geometry, text grouping, translation, mask, layout, inpainting, and rendering separately. Source pixels stay on disk during translation and are loaded from the page checkpoint as later stages need them; each page releases decoded images and intermediate arrays after its stage.
- Default English rendering font resolution (`get_default_eng_font()`) prioritizes Wild Words (`Wild Words.ttf`, `CC Wild Words Roman.ttf`, `wild_words.ttf`, etc.) when present in `fonts/`, falling back gracefully to bundled comic fonts (`anime_ace.ttf` / `comic shanns 2.ttf`).
- Translated-text placement runs after the response. Units with available translations are rendered onto the canvas even when flagged for manual review, with page-level baseline coordination, consistent font sizing, adaptive multi-line placement with relaxed bubble overflow fallback, and inpainting; failed/missing translation units restore their original pixels instead of leaving empty bubbles.
- Review-flagged text regions are rendered onto the canvas across backend pipeline rendering and web studio preview/editor while retaining explicit review flags, reasons, and badge indicators for subsequent review, draft saving, and approval in the studio.
- Speech bubble layout operates directly on arbitrary 2D free-space masks rather than rigid bounding boxes: uses Euclidean distance fields (SDF) to compute medial axes and boundary clearances, calculates spatial mask moments ($C_M, \Sigma_M$) and text inertia tensors ($C_T, \Sigma_T$) for orientation and aspect alignment, employs DP line breaking across horizontal span contours $C(y)$, and evaluates candidate layouts against centroid offset, inertia disparity, capacity utilization (~55–65% fill target with word-length bounds), raggedness, and linguistic boundaries. Candidate scoring accounts for FreeType ascender/descender metrics to avoid artificial box overflow, while prepared single-lobe and multi-lobe boxes composite directly into canvas points. Connected and multi-lobe bubbles balance word counts proportionally across spatial capacity while preserving uniform font sizing (with bounded per-lobe scaling when necessary), validating all glyph pixels against the safe shape with SDF margin clearance.
- Neural network model inference (detectors, OCR, bubble detection, inpainting, translators, upscalers) shares model instances through `SharedModelExecutor`; accelerator model calls are serialized, and GPU-capable stages wait for the accelerator slot instead of switching to CPU under contention.
- Production mask construction, shape-aware page layout, and text rendering use one process-wide bounded background CPU pool plus a separate interactive slot; batch rendering uses the background pool. OpenCV native threading is limited to one thread.
- Text detector checkpoints live under `models/detection/`; optional speech-bubble segmentation checkpoints live separately under `models/bubbles/`.
- Raw text detection bounding boxes (`detection.json`) and OCR textlines (`ocr.json`) are persisted immediately to disk and database storage upon stage completion, guaranteeing access to raw segmentation data prior to any downstream bubble grouping or translation filtering.
- Text grouping retains Unicode letters and numbers independently of translation eligibility using a 3-tier classification model (`MEANINGFUL_NUMERIC`, `POSSIBLE_NUMERIC`, `NOISE_NUMERIC`): intentional numeric regions (matching units/symbols/brackets, multi-digits, within/near speech bubbles or adjacent to linguistic text) and review-flagged possible numeric regions carry a `preserve` policy through translation checkpoints, are excluded from fast/professional provider payloads, and remain in masking, layout, and rendering at their measured source font size when available. Noise artifacts are filtered out.
- The page-detail and preview image components display detector polygon outlines color-coded by confidence tier (emerald $\ge 85\%$, amber $65\%-84\%$, rose $< 65\%$) with interactive hover highlights and floating tooltips showing exact confidence percentages (e.g. `#4 · 94% · high`), eliminating visual clutter on multi-line Japanese text.
- The web studio exposes OCR model selection and OCR Minimum Confidence threshold (`customOcrProb` / `ocrMinConfidence`), mapped to `OcrConfig.prob` and persisted across settings, batch jobs, and pipeline manifest metadata; every registered OCR backend applies the setting to its final text-region output.
- Backend OCR defaults use the registered `48px_ctc` model; alternate OCR models remain selectable through the enum and shared web options.
- Manga OCR (`mocr`, `kha-white/manga-ocr-base`) downloads complete model assets directly into `./models/ocr/` and loads offline from that directory when present; `docker_prepare.py` supports preparing `mocr` via `--models ocr.mocr` (or `mocr`).
- Result metadata (`meta.json` and `pipeline_manifest.json`) captures comprehensive pipeline step parameters (detector, resolution, box threshold, unclip ratio, OCR model, OCR min confidence, bubble detection settings, inpainting parameters, rendering configurations, colorizer, and upscaler); the web studio `PageDetailModal` displays these in a tabbed resizable sidebar with four tabs — Pipeline Timing (started/ended/duration + per-stage breakdown), Professional Localization, Story Analysis, and Step Settings (translation details + all step parameters). The sidebar defaults to 480 px wide and is drag-resizable from its left edge (280–700 px range).
- The batch SSE stream sends changed full batch details to the Web Studio; loaded items update live without follow-up detail GETs, while REST detail reads occur on first expansion only.
- Manga summary job lists and open summary progress now share an SSE stream; the server publishes changed snapshots and clients fetch the full summary only once the job reaches a terminal state.
- Search Lab status and embedding progress also use a change-only SSE stream; explicit refresh still performs a one-time status read.
- Dropping or uploading loose image files loads them directly into the studio cards list without intermediate staging, while multi-archive drops retain volume arrangement before extraction. Manga detail gallery supports smooth proximity-accelerated vertical auto-scrolling when dragging pages near viewport edges during page reordering. Selecting multiple pages or multiple manga cards supports batch deletion with confirmation prompts and atomic cache and state invalidation.
- Translated text lettering case can be configured to original (mixed case), ALL CAPS (uppercase), or lowercase across CLI arguments (`--uppercase`, `--lowercase`, `--letter-case`) and server batches/Web Studio options; English typesetting segmenters preserve original case without hardcoded upper-casing.
